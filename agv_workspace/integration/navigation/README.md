# 导航栈（Nav2）集成

第一版范围：静态集成，不回放实车运动、不下发自主运动目标。

- 全局规划器：SmacPlanner2D（差速车）
- 局部控制器：DWB（先验证基础链路；MPPI 待基础跑通后同场景实测对比）
- 代价地图：global + local 两层，local 用主雷达 188° 前向 scan 作为观测源
- 速度上限保守：max_vel_x 0.3、max_vel_theta 0.5，不触碰 MCU -0.6..1.5 m/s、±1.0 rad/s 上限

## 冻结边界
- 不改雷达/MCU/IMU/协议、EKF、AMCL、定位阈值、协方差规则
- 不接 cmd_vel 放行（运动授权 SW-018 是后续硬门）
- 不加自动重试、旧路径复用、动态参数重载

## 验收
- 代码通过：nav2 参数可加载、规划器插件可实例化
- 回放规划通过：用已保存地图 + run95 的 scan/odom 回放，能生成 A→B 路径，
  且 0.8m 直廊不被膨胀半径封死

## 窄通道与膨胀半径的硬约束

已用两遍欧氏距离变换对当前保存地图（61×213 格 @ 5cm）量化，结论：

- 自由格到最近墙距离：中位 5 格（0.25m），到墙 ≥0.30m 的自由格占 43.7%，
  到墙 ≥0.40m 仅 1803 格，≥0.80m 仅 5 格。
- 车旋转包络半径 0.425m（sqrt(0.65²+0.55²)/2），半宽 0.275m。

可通行判据：`通道中心到墙距离 - inflation_radius ≥ 车半宽`。对当前地图最窄
可通行处（到墙约 0.30m），最大允许的额外膨胀只有约 0.025m。因此：

- 起步用 `inflation_radius: 0.10`（2 格），`cost_scaling_factor: 3.0`，
  宁可保守贴墙，先保窄通道可通行。
- 车体安全圈由 `robot_radius: 0.30` 承担；`inflation_layer` 是额外墙外惩罚，
  不是车体安全圈，不要叠加成双倍。
- 现场必须先实测最窄通道宽度 W，再按 `inflation_radius_max = W/2 - 0.275`
  标定，不能用社区模板值（0.35/0.40）直接套。

## 建图质量阻塞（导航前必须先解决）

对当前保存地图的连通性分析：

- 仅 `free`（0）：6450 格，分成 32 个连通分量，纵向不贯通。
- `free + unknown`：11942 格，13 个分量，纵向贯通。
- 地图 46% 是 unknown（-1），free 被 unknown 切碎成 32 块。

结论：当前 `global_costmap` 若 `track_unknown_space: true`，unknown 视为不可
通行，导航会因地图碎片化而无法规划贯通路径。这是 `slam_toolbox` 建图扫描
覆盖不足留下的 unknown，不是 nav2 膨胀参数能修的。调膨胀半径解决不了
连通性断裂。

阻塞项：需要重新建图（提高扫描覆盖、减少 unknown），或在代价地图把
unknown 作为可通行处理，但后者会牺牲安全性。未重新建图前，不要进入
实车导航调参。
