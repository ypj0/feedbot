# Phase 2 规划：定位模块（Localization）

## 现状与约束

**约束**（来自 Phase 1A）：
- ✅ 运动出口统一（MotionAuthority → /wheel/cmd_vel）
- ✅ Time 单调性保证（steady_clock 注入）
- ✅ 50Hz 控制周期冻结
- ✅ EKF/TF 链固定（odom→base_link by ekf_filter_node）

**问题**：
- 原厂依赖启动时读 `/tracked_pose`（需要与原厂连接），与"不用原厂行为"冲突
- 需要独立的初值方案，不依赖原厂

---

## Phase 2 目标

**输入**：
- `/scan` ≈15 Hz（LiDAR）
- `/odometry/filtered` ≈50 Hz（EKF）
- `/tf` chain（odom→base_link）

**输出**：
- `/tf` map→odom（AMCL 发布）
- 定位在地图上的初值方案

**不做**：
- 地图编辑/编码算法优化（单独 Phase 4）
- 循环闭合/回环检测（单独后续阶段）

---

## 初值方案选项

### 选项 1：网页手点初始位姿（推荐第一阶段）

**流程**：
1. 加载已有地图（第 4 阶段前）
2. 操作员在网页上标记当前位置和朝向
3. 写入 `/initialpose` 话题（nav2 标准接口）
4. AMCL 以此为起点，通过激光匹配细化

**优点**：
- 完全独立，无需外部依赖
- 交互式，易于调试
- 与 Nav2 生态兼容

**缺点**：
- 需要有地图
- 操作员需手工输入

**实现**：
- 网页添加地图画布（来自已保存的 OccupancyGrid）
- 鼠标点击设置位置和方向
- POST 到后端发布 `/initialpose`

### 选项 2：固定充电桩起点

**流程**：
1. 车机启动时，自动移动到充电桩（固定位置）
2. 读取 URDF 中的充电桩坐标
3. 以该坐标为初值启动 AMCL

**优点**：
- 完全自动，无需操作员干预
- 可靠性高

**缺点**：
- 每次启动都要回充电桩
- 不灵活

**实现**：
- 在 URDF 中标记充电桩位置
- 启动脚本中硬编码初值

### 选项 3：二维码/标记物定位

**流程**：
1. 在已知位置贴二维码或特殊标记物
2. 车机识别标记物
3. 读取标记物的 ID 和已知位置，作为初值

**优点**：
- 自动化
- 可在多个位置启动

**缺点**：
- 需要标记物基础设施
- 识别算法复杂

**实现**：
- ArUco 标记物或其他视觉标记
- 单独识别节点
- 映射表（标记物 ID → 地图坐标）

---

## 推荐方案：选项 1（网页手点）

**理由**：
- Phase 1A 已经有最小网页 UI（遥控 + 状态）
- 添加"地图 + 初值点击"是自然扩展
- 不需要额外硬件或基础设施
- 与 Phase 2 验收（地面标定）流程协调

**工作量**：
- 网页：地图加载 + 点击交互（1-2 天）
- ROS 2：`/initialpose` publisher（<1 小时）
- 测试：与 AMCL 集成验证（1 天）

## Phase 2 分切片规划

### Slice 1：AMCL 配置与集成
- [ ] AMCL 参数冻结（激光噪声/里程计噪声/粒子数等）

- [ ] 验收：手点 3-5 个位置，AMCL 均收敛

### Slice 3：导航集成预备
- [ ] Nav2 参数冻结
- [ ] `/goal` 话题通路打通

- [ ] 已知初值→AMCL 收敛（< 0.5m 误差）

- [ ] 多地点测试（确保不是某个位置过拟合）

## 契约扩展（Phase 2）

```yaml
phase_2_localization:
  timing:
    amcl_rate_hz: 10        # AMCL pose 更新频率
    amcl_timeout_ms: 300    # 允许的最大更新延迟
    
  limits:
    max_particle_count: 2000  # 粒子数
    min_converged_particles: 1500  # 收敛判定

  topics:
    initialpose: /initialpose         # 初值输入
    amcl_pose: /amcl_pose             # 定位输出
    particlecloud: /particlecloud     # 粒子云（调试）
    map: /map                         # 地图
```

## 技术决策

| 决策项 | 选择 | 原因 |
|--------|------|------|
| 初值方案 | 网页手点 | 灵活、无额外依赖 |
| AMCL 源 | nav2 官方 | 标准 ROS 2 包 |
| 粒子数 | 2000 | 平衡准确度和 CPU（50Hz × 50 个粒子/步） |
| 匹配算法 | adaptive_likelihood_field | 鲁棒性 |
| 更新方式 | velocity 模型 | Phase 1A 中已有里程计 |

## Phase 2 验收门槛

**定位精度**：
- 已知初值情况下，收敛误差 < 50cm
- 长时间运行（10分钟），累积漂移 < 1m

**稳定性**：
- 无异常发散（粒子散射到地图外）
- `/amcl_pose` 频率稳定在 10 Hz
- CPU/内存无异常峰值

**可靠性**：
- 在 5 个不同位置测试，均能正常定位
- 重启后初值重新设置，定位重新收敛

## 后续决策点

**如果 AMCL 收敛困难**：
- 检查地图质量（地图编制需要调整？）
- 检查激光传感器 `/scan` 是否与地图匹配
- 增加粒子数或调整匹配参数

**如果需要多初值支持**：
- 加入二维码识别（选项 3）
- 或固定多个常用起点（选项 2 变体）

**如果需要离线地图**：
- Phase 4 完成前，使用原厂地图或测试地图
- Phase 4 后，自有生成的地图
